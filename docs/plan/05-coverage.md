# BEAM coverage matrix

This file is the coverage matrix of runbook rule BS-19 (`docs/plan/04-build-session.md`). It maps every section of the blueprint (`docs/requirements/beam-blueprint.txt`) and every promise of the proposal (`docs/requirements/proposal.md`) to the module, the build package (`docs/plan/build-packages.json`) and the test that delivers it.

Written by the completeness critic, round 2, on 2026-11-03. It replaces the round 1 matrix. Sources: the blueprint (all 89 sections), the proposal, `00-decisions.md`, `01-architecture.md`, `02-data-model.md`, `03-build-order.md`, `04-build-session.md` (BS-19), `build-packages.json` and the twelve module specs.

Round 2 checks, beyond round 1: every test file named in this matrix was looked up in the `tests` and `owns` lists of `build-packages.json` (all exist, in the package named); every Playwright spec of a package runs at a checkpoint of `03-build-order.md` section 7 (none is left out); every module spec's "Later" row was compared with the proposal's "Later" row; vague test references of round 1 ("crm-P8 pipeline tests") are replaced by file paths. New gaps are G8 to G13 in Part F.

## How to read it

**Coverage** (decided by the critic, fixed in this file):

- **full**: every requirement of the row is built in V1, scheduled in a named release with a named package, or excluded as "Later" in line with the proposal (section 2, row "Later") or a module spec's "Later (out of scope)" row that the proposal allows.
- **partial**: most of the row is covered, but at least one requirement has no package or test. The gap column says what is missing and the decision taken.
- **missing**: nothing in the plan covers the row.
- **excluded**: the whole row is out of scope, in line with the proposal.
Rows that ask for a written commitment rather than software (blueprint 57, 68, 69, 74, 75, 86) are **full** when the proposal answers them and a plan package writes the handbook or runbook page that proves it; their gap text starts with "Contract row". In Part E, the release value `contract` means the promise is carried by the agreement annexes.

**Status** is filled by the orchestrator at each checkpoint of `03-build-order.md` section 7. Values: `planned` (not built yet), `built` (package merged, its tests green), `accepted` (the acceptance test of the row passed at a checkpoint), `blocked` (with an issue id from `docs/build/`). Every row starts as `planned`.

**Releases:** V1 = weeks 1-6 (waves 0-11), R2 = weeks 9-10 (waves 12-18), R3 = weeks 11-12 (waves 19-21), R4 = weeks 13-14 (waves 22-23), Later = after the build-out, by separate proposal.

**Test paths** are relative to `apps/web/` unless they start with `packages/`.
